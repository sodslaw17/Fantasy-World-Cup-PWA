The hard rules · SPEC §11.3 / §11.5

Contrast guardrail & per-user theming

Flag colors are an accent layer only — the white base and body text never change. When a flag color would fail contrast it is auto-adjusted, never rendered unreadable. Port lib/theme.ts exactly; never hand-pick a contrast.

The rule that keeps it legible

TokenUse
--brandraw flag fill — active states, headers
--brand-inkbrand as TEXT on a surface (AA-guaranteed)
--brand-ontext/icon sitting ON a brand fill
--brand-softtint for soft chips/cards

Anything that renders text uses --brand-ink or --brand-on — never raw --brand.

computeBrand(primary, secondary, base) → {
  "--brand": primary,
  "--brand-ink": ensureContrast(primary, surface, 4.5),
  "--brand-on": onColor(primary),
  "--brand-soft": mixHex(primary, surface, .88),
  "--brand-2": secondary,
  "--brand-2-ink": ensureContrast(secondary, surface, 4.5),
}
// <div data-base={base} style={brandVars}>…

The Claude Code prompt

  • 1Presentation only. No logic / data / behavior changes — markup & classes.
  • 2Read existing files first; refactor them to use the shared components. Never scaffold new routes.
  • 3Render only what the design shows. No invented fields/sections (remember the timezone select).
  • 4Reuse tokens — never inline a hex. Only data-driven colors (user/flag) arrive as props.
  • 5Fonts must load (next/font); verify titles are Saira Condensed, not the body sans.
  • 6WCAG AA everywhere via lib/theme.ts; all tap targets ≥44×44.
  • 7Preserve per-user knockout flag theming + the name+icon rules. Gold = winner/payout only.
  • 8Mobile-first user pages; desktop-first responsive admin. Drop the PhoneFrame bezel.
  • 9Work page-by-page; after each, confirm only presentation changed. Finish with a files-changed summary. Reference SPEC §9 & §11.
